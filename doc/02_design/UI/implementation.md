情報設計・レイアウトをコードに落とすときの注意。

---

## グループ構造を単純に保つ

- 画面は **Screen → Panel → Component** の浅さに合わせる
- AI 生成 HTML の深いネストは採用せず、各画面・パネル文書の親→子に書き直す

---

## リストはデータ駆動

| UI | セル定義 | 繰り返し元 |
|----|----------|------------|
| 調教師候補 | 1行（氏名等） | 検索結果配列 |
| 重賞勝利 | 1行（日付・レース等） | 分析結果配列 |
| ナビ | NavItem | 画面インベントリ順（ホーム / 募集馬 / 調教師 / 生産牧場 / 血統 / 設定。複数頭比較は除外） |
| ホーム遷移 | NavCard | 遷移先定義配列（募集馬 / 調教師 / 生産牧場 / 血統 / 設定） |
| ダッシュボード本文 | module 別 View | 調教師 / 生産牧場 / 血統と共用（similarity のみ専用） |

---

## 表示時に再集計しない

チャート・表は ViewModel（SQLite 分析結果の読取）をそのまま描画する。更新パイプラインは ホーム / 設定 / ヘッダから実行。

---

## 表示フォーマット（情報設計 §2.11）

UI は解釈済み値を受け取り、画面側で再換算しない。

| 項目 | 表示 |
|------|------|
| 金額 | 千円区切り＋「円」 |
| 率 | `%`（小数桁は全画面統一） |
| 着回数 | 整数。ゼロは `0` |
| 日付 | `YYYY-MM-DD` |
| 最終更新 | `YYYY-MM-DD HH:mm`（ローカル） |
| 欠損 | 「—」または「データなし」 |

---

## 単体画面とダッシュボードの共用

調教師・生産牧場・血統の分析本文は単体画面と募集馬ダッシュボードで同一コンポーネント（情報設計 §3.1）。埋め込み時は検索 UI を重複させず、フォーム／選択 context を渡す。
