---

## トーン

| 項目 | 方針 |
|------|------|
| 印象 | 分析ツールらしい **落ち着いたコントラスト**。競馬・出資の意思決定を邪魔しない |
| 密度 | デスクトップ向けに情報密度高め。装飾カードやダッシュボード風ウィジェットの乱用はしない。ホームの `NavCard` は遷移の操作入口としてのみ許容 |
| 言語 | UI 文言は日本語 |
| ブランド | ヘッダに「EquiScout」を常時表示 |

---

## 揃える対象

| 対象 | 本章での決定 | 詳細の置き場 |
|------|--------------|--------------|
| 色（背景・文字・強調・エラー） | `base_desing.md` でトークン化 | 同左 |
| フォント | 本文可読性優先。デフォルトシステム丸投げは避ける方針を base で定義 | `base_desing.md` |
| 余白・角丸・ボーダー | パネル区切りは弱め。表と見出しで階層 | `base_desing.md` |
| チャート | 棒グラフ中心。色数は最小（芝/ダート・系列） | ライブラリは実装時（アーキ 7.1） |
| ボタン | Primary = 分析表示・データ更新・ホームからの主遷移。Secondary = クリア等 | 形状トークンは base |
| プレースホルダ / Empty | 謝罪調にしない。短文＋将来載せる内容 | 文言は情報設計、見た目は base |

---

## 状態の見た目（最低限）

| 状態 | ビジュアル要件 |
|------|----------------|
| エラー | `ErrorBanner` は本文より先に目に入る位置・コントラスト |
| 更新中 | ヘッダの進捗は控えめだが無視できない |
| 必須エラー | フィールド下のテキスト。赤系はトークンに従う |
| プレースホルダ | 本文エリアと区別できるが「壊れた画面」に見えないこと |

## AI / 生成ツールに渡す指示（任意）

- デバイス: デスクトップ、左ナビ＋メイン（起動はホーム）
- 実装前提: React + TypeScript（のち Electron）。深いネストや装飾カード多用は避ける
- トーン: 上記。紫グラデや過剰なグローは使わない
- ホーム: 遷移カードは操作入口として許容（装飾ウィジェットではない）。分析指標のプレビューは載せない
