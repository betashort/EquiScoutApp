## 1. 本書の目的と進め方

### 1.1 目的

要求の操作フロー（1頭分析 / 単体分析 / 将来の複数頭比較）と、アーキテクチャ上の Presentation コンポーネント（C01〜C08）を対応づけ、画面仕様を定める。

画面設計を「1枚の絵」として扱わず、次の **3層をこの順で確定** する（[参考記事](https://note.com/john01/n/nd4da0d5f8841)）。

| 層 | 決めること | 本書での扱い |
|----|------------|--------------|
| **1. 情報設計** | 何を載せるか、優先順位、載せないもの、ゴール | **正本。人が握る** |
| **2. レイアウト** | どこに置くか、読む順序、パネル／ワイヤ | 情報設計を配置に落とす |
| **3. ビジュアル** | 配色・フォント・余白・トーン | 方針のみ。詳細は `base_desing.md` |

### 1.2 設計方針（横断）

| # | 方針 | 根拠 |
|---|------|------|
| 1 | **分析ダッシュボードを共通枠**とし、分析種類は切替で埋め込む | 要求 3.1 / アーキ C03 |
| 2 | **調教師分析ビューは単体画面とダッシュボード埋め込みで共用**する | 要求 3.1・3.3 / C04 |
| 3 | MVP は調教師を実データ、牧場・血統・類似馬は骨格／プレースホルダ | 要求 4 MVP |
| 4 | 募集馬は **画面先行**（フォーム状態のみ。永続化は後続） | アーキ 6.3 |
| 5 | 表示は分析済みデータの読取のみ。重い集計は UI で行わない | アーキ Presentation |
| 6 | 強さ・コスパ・複数頭ランキングは **載せない**（MVP） | 要求 4 / feature flag |
| 7 | UI 言語は日本語。デスクトップ（のち Electron）前提 | 要求 6 / アーキ 9.1 |

### 1.3 用語（画面の分解単位）

情報設計・レイアウトの記述に使う単位。ビジュアルの部品名ではない。

| 単位 | 意味 | 例 |
|------|------|-----|
| **画面 (Screen)** | ナビで遷移する単位 | 調教師単体分析 |
| **パネル (Panel)** | 画面内の役割が1つの区画 | 検索、賞金サマリ |
| **コンポーネント** | 再利用可能な UI 塊 | `EntitySearchBox`、`MetricTable` |
| **UI要素** | 入力・表示の最小単位 | テキストフィールド、表セル |

### 1.4 情報設計の書き方（各画面共通）

各画面は次の4点を必須とする（参考記事の型）。

1. **役割**（一文）
2. **載せる要素**（上から優先順位順）
3. **載せない要素**
4. **ゴール**（読まれたい情報 / 押されたい操作）

## 2. 第1層：情報設計

> 「この画面に何を載せるか、どの優先順位で載せるか」を決める層。  
> レイアウトや見た目より先に、ここを確定する。

### 2.1 画面インベントリとナビ上の優先

| 優先 | ID | 画面名 | MVP | 備考 |
|------|-----|--------|-----|------|
| 1（本線） | S02 | 調教師単体分析 | ○ 実データ | 起動時ランディング推奨 |
| 2 | S01 | 募集馬1頭分析 | ○ | ダッシュボード埋め込みで調教師を共用 |
| 3 | S06 | データ更新・設定 | ○ | 全画面から到達 |
| 4 | S03 | 生産牧場単体分析 | ○ 骨格 | 導線のみ確保 |
| 5 | S04 | 血統単体分析 | ○ 骨格 | 導線のみ確保 |
| — | S05 | 複数頭比較 | × | ナビに出さない |

```text
ナビに出す（MVP）: 募集馬 / 調教師 / 生産牧場 / 血統 / 設定（または更新）
ナビに出さない: 複数頭比較、強さ・コスパ専用画面
```

### 2.2 画面遷移（情報の流れ）

```text
[起動] → S02（推奨）または S01
S01 入力完了 → 同一画面内で分析ダッシュボード（遷移なし）
S02/S03/S04 → 候補選択後、同一画面内で分析表示（遷移なし）
どこからでも → S06（更新）
S05（将来）1頭選択 → S01 相当のダッシュボード
```

デフォルト表示のユーザー設定は P1。MVP は固定。

### 2.3 S02 調教師単体分析（MVP 本線）

| 項目 | 内容 |
|------|------|
| **役割** | 馬入力なしで調教師を選び、成績指標を読んで比較材料にする |
| **ゴール** | ① 名前で候補を選ぶ ② 賞金・着回・率・距離・重賞を上から読む |

**載せる要素（優先順）**

1. 調教師名の検索（テキスト）と候補一覧
2. 選択中の調教師名（対象の確認）
3. 賞金（本年 / 前年 / 累計 × 本賞金・付加賞金）
4. 着回数（本年 / 前年 / 累計 × 1〜5着・着外）
5. 勝率・連対率・複勝率（本年 / 前年 / 累計）
6. 距離別着回数（芝 / ダート × 距離帯）
7. 最近の重賞勝利一覧

**載せない要素（MVP）**

- 勝率ランキング一覧からの選択
- 多年推移グラフ、クラス別・新馬・勝ち上がり（P1）
- 強さ / コスパスコア
- 募集馬フォーム（S01 の責務）

**対応アーキ / UC:** C04 / `searchTrainers` / `getTrainerAnalysis`

### 2.4 S01 募集馬1頭分析

| 項目 | 内容 |
|------|------|
| **役割** | 募集馬の必須属性を入力し、同一画面で分析種類を切り替えて読む |
| **ゴール** | ① 必須入力を完了して「分析を表示」 ② 調教師分析（実データ）を同一画面で確認 |

**載せる要素（優先順）**

1. 必須プロフィール: 生年月日、性別、毛色、体重（募集時・手入力）
2. 血統キー: 母名、父名（候補選択）
3. 関係者: 調教師、生産牧場、産地、馬主
4. 価格: 市場取引価格（主）。1口価格・口数は任意の補助
5. アクション: 「分析を表示」／「クリア」
6. 分析ダッシュボード: 分析種類切替 ＋ 埋め込み本体  
   - 優先して読ませる: **調教師分析（実データ）**  
   - 枠として載せる: 生産牧場 / 血統 / 類似馬（骨格・プレースホルダ）

**載せない要素（MVP）**

- 募集馬の保存・下書き一覧（後続）
- 強さ・コスパ総合評価タブ
- 複数頭入力

**対応アーキ:** C02 + C03（埋め込み C04〜C07）

### 2.5 分析ダッシュボード（共通・情報設計）

S01（および将来の比較からの遷移）で共用する「分析の中身」の優先と除外。

| 優先 | moduleId | ラベル | MVP で載せるか | 中身の方針 |
|------|----------|--------|----------------|------------|
| 1 | `trainer` | 調教師分析 | ○ | S02 と同じ指標一式（実データ） |
| 2 | `farm` | 生産牧場分析 | ○ 枠 | 準備中＋将来内容の明示 |
| 3 | `pedigree` | 血統分析 | ○ 枠 | 同上（SMILE・馬場・兄弟は後続） |
| 4 | `similarity` | 類似馬・参考成績 | ○ 枠 | 条件未定（PoC）のプレースホルダ |
| — | `strength_cost` | 強さ・コスパ総合 | **載せない** | PoC 後 |

調教師埋め込み時に載せる指標の優先順は **S02 の載せる要素 2〜7 と同一**（再利用）。

### 2.6 S03 生産牧場単体分析（骨格）

| 項目 | 内容 |
|------|------|
| **役割** | 生産者＝牧場を単体で調べる導線を確保する（本実装は後続） |
| **ゴール** | 牧場を選べること。中身は「準備中」で将来範囲が分かること |

**載せる要素（優先順）**

1. 牧場名検索と候補
2. プレースホルダ（将来: 本年/累計の賞金・着回数、出身馬リスト）

**載せない要素（MVP）:** 実集計表、出身馬一覧の本実装

### 2.7 S04 血統単体分析（骨格）

| 項目 | 内容 |
|------|------|
| **役割** | 血統を単体で調べる導線を確保する（本実装は後続） |
| **ゴール** | 父・母などのキーを入れられること。中身は将来範囲が分かること |

**載せる要素（優先順）**

1. 父名・母名などのキー入力（候補）
2. プレースホルダ（将来: 距離適性 SMILE / 馬場適性 / 兄弟成績）

**載せない要素（MVP）:** SMILE 本集計、兄弟成績表の本実装

### 2.8 S05 複数頭比較（MVP外）

| 項目 | 内容 |
|------|------|
| **役割** | （将来）複数頭を入力し強さ・コスパでランキングする |
| **ゴール** | —（MVP 対象外） |

**載せない（MVP）:** 画面自体をナビに出さない。ルートを生やす場合も Empty のみ。

将来の載せる要素案: 複数頭リスト → ランキング表 → 1頭選択でダッシュボード。

### 2.9 S06 データ更新・設定

| 項目 | 内容 |
|------|------|
| **役割** | JV-DL 正本から手動更新し、接続と更新結果を確認する |
| **ゴール** | 「データを更新」を実行し、成功/失敗と最終更新日時が分かること |

**載せる要素（優先順）**

1. 更新実行と進捗（Sync / Analyze）
2. 結果サマリ（件数・所要時間・エラー）
3. 最終更新日時（シェルにも同一情報を出す）
4. PG 接続設定（ローカルのみ）
5. （任意）SQLite パスの読取表示

**載せない要素:** クラウド同期、定期更新の必須 UI、マルチユーザー認証

**対応アーキ / UC:** C08 / `updateFromPostgres` / `getUpdateStatus`

### 2.10 状態として伝える情報（全画面共通）

載せる「状態メッセージ」の優先。見た目はレイアウト／ビジュアル層。

| 優先 | 状態 | 伝えること |
|------|------|------------|
| 1 | 未選択 | 次に何をすればよいか |
| 2 | エラー | 失敗理由と、可能なら再試行 |
| 3 | 更新中 | 進行中である（操作は継続可） |
| 4 | 読取中 / 検索中 | 待ちであること |
| 5 | 0件 | 候補なし・重賞なし等 |
| 6 | 未実装モジュール | 準備中＋将来載せる内容 |

S01 バリデーション: 必須欠落は「分析を表示」時にフィールド単位で伝える。

### 2.11 表示データの意味ルール（情報の解釈）

UI は生カラムではなく解釈済み値を受ける（アーキ 8.2）。情報として揃えるルール:

| 項目 | ルール |
|------|--------|
| 金額 | 千円区切り＋「円」（換算は ViewModel 側で完了） |
| 率 | `%`。小数桁は全画面統一 |
| 着回数 | 整数。ゼロは `0` |
| 日付 | `YYYY-MM-DD` |
| 最終更新 | `YYYY-MM-DD HH:mm`（ローカル） |
| 欠損 | 「—」または「データなし」 |

## 3. 第2層：レイアウト

> 情報設計で決めた要素を、画面上のどこに置き、どの順で読ませるか。  
> デスクトップ（のち Electron）を前提。狭幅は1カラム折りたたみを許容。

### 3.1 デバイスと全体骨格

| 項目 | 決定 |
|------|------|
| デバイス | **デスクトップ優先**（主に Windows、macOS 対応） |
| 全体 | 左ナビ ＋ ヘッダ（タイトル / 更新 / 最終更新）＋ MainContent |
| 読取方向 | 上→下。分析本文は1カラム縦積み（MVP 固定） |

```text
┌──────────────────────────────────────────────────────────┐
│ EquiScout          [更新]  最終更新: YYYY-MM-DD HH:mm     │  ← ヘッダ
├──────────┬───────────────────────────────────────────────┤
│ 募集馬   │                                               │
│ 調教師   │              MainContent                      │  ← 各 Screen
│ 生産牧場 │                                               │
│ 血統     │                                               │
│ ──────── │                                               │
│ 設定     │                                               │
└──────────┴───────────────────────────────────────────────┘
     ↑ グローバルナビ
```

**親→子（実装用グループ）**

```text
AppShell
├─ HeaderBar（タイトル / UpdateShortcut / UpdateStatusChip）
├─ GlobalNav（NavItem × 画面）
└─ MainContent（Screen を1つマウント）
```

### 3.2 共有コンポーネント（配置の部品）

情報設計の要素を載せるための部品カタログ。見た目トークンは第3層。

| ID | コンポーネント | 載せる情報の例 |
|----|----------------|----------------|
| U01 | `EntitySearchBox` | 名前検索 |
| U02 | `CandidateList` | 候補選択 |
| U03 | `AnalysisTypeSelect` | 分析種類 |
| U04 | `EmptyState` | 未選択・案内 |
| U05 | `PlaceholderPanel` | 未実装枠 |
| U06 | `MetricTable` | 賞金・着回数 |
| U07 | `RateBadgeRow` | 勝率・連対・複勝 |
| U08 | `BarChart` | 距離別 |
| U09 | `DataTable` | 重賞一覧など |
| U10 | `FormField` | ラベル付き入力 |
| U11 | `SectionHeader` | パネル見出し |
| U12 | `LoadingBlock` | 読取中 |
| U13 | `ErrorBanner` | エラー |
| U14 | `PrimaryButton` / `SecondaryButton` | 主／副アクション |

リストは **1セル定義＋データ繰り返し**（候補・重賞行など）。同型を複製配置しない。

情報優先順に対応する配置: **検索（上）→ 分析本文（下・縦積み）**。

**ワイヤ**

```text
┌─ 調教師を探す ─────────────────────────────────────────┐
│ 名前 [________________________]                        │
│  ┌ 候補 ─────────────────────────────────────────────┐ │
│  │ 〇〇 調教師                                        │ │
│  │ △△ 調教師                                        │ │
│  └───────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────┘
┌─ 〇〇 調教師 ──────────────────────────────────────────┐
│ 【賞金】 本年/前年/累計 × 本賞金・付加賞金              │
│ 【着回数】 1〜5着・着外                                 │
│ 【率】 勝率 / 連対率 / 複勝率                           │
│ 【距離別】 (芝|ダート)  [棒グラフ] + 表                 │
│ 【最近の重賞勝利】 日付|レース|G|馬名|…                 │

```

| パネル | コンポーネント | 配置メモ |
|--------|----------------|----------|
| P-S02-A | `EntitySearchBox`, `CandidateList`, `EmptyState`, `LoadingBlock` | 画面上部。候補は入力直下 |

| B4 | `RateBadgeRow` | 率は表の直後（視線の流れ） |
| B5 | タブ/トグル + `BarChart` + `MetricTable` | グラフ主、表は併置 |
| B6 | `DataTable` | 最下部。0件は Empty |

S01 の trainer 埋め込み時も **同一コンポーネント・同一縦順**（ProfileHeader はダッシュボード副題と重複するなら省略可）。

シェルヘッダの [更新] は A と同じユースケース。更新中はヘッダに進行表示し、MainContent はブロックしない。

設定は情報量が少なければ **モーダル**でも可（配置の実装選択）。

## 4. 第3層：ビジュアル

### 4.1 トーン（プロダクト）

| 項目 | 方針 |
|------|------|

| 密度 | デスクトップ向けに情報密度高め。装飾カードやダッシュボード風ウィジェットの乱用はしない |
| 言語 | UI 文言は日本語 |

### 4.2 ビジュアルで揃える対象

| 対象 | 本章での決定 | 詳細の置き場 |
|------|--------------|--------------|
| 色（背景・文字・強調・エラー） | `base_desing.md` でトークン化 | 同左 |
| フォント | 本文可読性優先。デフォルトシステム丸投げは避ける方針を base で定義 | `base_desing.md` |
| 余白・角丸・ボーダー | パネル区切りは弱め。表と見出しで階層 | `base_desing.md` |
| チャート | 棒グラフ中心。色数は最小（芝/ダート・系列） | ライブラリは実装時（アーキ 7.1） |

| プレースホルダ / Empty | 謝罪調にしない。短文＋将来載せる内容 | 文言は情報設計、見た目は base |

### 4.3 状態の見た目（最低限）

| 状態 | ビジュアル要件 |
|------|----------------|
| エラー | `ErrorBanner` は本文より先に目に入る位置・コントラスト |

| 必須エラー | フィールド下のテキスト。赤系はトークンに従う |
| プレースホルダ | 本文エリアと区別できるが「壊れた画面」に見えないこと |

レイアウト確定後に見た目案を出す場合の指示例:

## 7. 未決・委譲・まとめ

### 7.1 未決・委譲

| 項目 | 委譲先 |
|------|--------|
| 色・フォント・スペーシングのトークン | `base_desing.md`（第3層の詳細） |

### 7.2 まとめ

画面設計は **情報設計 → レイアウト → ビジュアル** の順で進める。情報設計では S02 を本線に「載せる／載せない／ゴール」を固定し、レイアウトではデスクトップの左ナビ＋縦積みでその優先順をそのまま配置する。ビジュアルはトーンと制約だけを本章に残し、トークンは `base_desing.md` に委譲する。実装時は浅い Panel 構造とリストのデータ駆動を守り、AI 生成の見た目に情報設計を上書きさせない。
