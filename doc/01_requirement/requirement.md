# EquiScout 要求分析

## 1. プロダクト概要

### 目的

* 強い競走馬を選びたい
* コスパ（強さ・価格のバランス）が良い競走馬を選びたい
* 一口馬主クラブの募集馬を選ぶための情報を分析・可視化したい

### 利用者・利用シーン

* 主な利用者: 個人の一口馬主希望者
* 利用シーン:
    * 募集期間中に候補馬を比較する
    * 通年で調教師・牧場・血統を調べる

### 対象データ範囲

* JV-DL で取得できるレース・関連マスタを対象とする

---

## 2. 「強さ」「コスパ」の定義

方針は以下とする。**計算式・定量化ルールは未定**とし、PoC で検証してから実装する。

### 強さ（方針）

* 1次指標: 重賞で勝てる確率が高い馬が強い（G1 > G2 > G3 の順で重視）
* 2次指標: 負けない馬が強い（馬券内に入り安定している、大負けしない）
* スコアの定量化、1次/2次の合成、未出走馬の代理指標、「大負け」の定義は **未定（PoC）**
* MVP では強さスコアの算出・表示は行わない

### 価格

* コスパ評価の基準は JV-DL の市場取引価格（HS）を**意図的に**用いる
* 理由: 市場取引価格と「出資金 × 募集口数」はほぼ同額とみなせる
* 募集馬1頭分析では、入力として **1口価格** と **口数** を用意してもよい（市場取引価格の代替・併記用）
* 将来（MVP外）: 一口出資額との併用も検討する

### コスパ（方針）

* 強さ指標と価格を組み合わせて評価する
* 具体的な計算式（除算・価格帯相対・並置のみ等）は **未定（PoC）**
* MVP ではコスパスコアの算出・表示は行わない

### 評価の出力方針（PoC後）

* スコア（数値）とその根拠となるデータを、グラフ等で可視化する

## 3. 機能要求

### 3.1 操作フロー（複数機能）

1. **1頭分析**: 募集馬を1頭入力 → その馬の分析ダッシュボードを表示する
2. **複数頭比較**: 複数頭を入力 → ランキング（強さ指標・コスパ指標）を表示する。1頭を選択すると 1. の分析ダッシュボードを表示する（**スコア定義確定後。MVP外**）
3. **単体分析**: 調教師 / 生産牧場 / 血統を単体で調べ、分析ダッシュボードを表示する（馬入力なし）

### 3.2 分析ダッシュボードの出力内容

以下をすべて表示できること（完成形）。デフォルトの表示状態は設定可能とする。

* 調教師分析
* 生産牧場（生産者）分析
* 血統分析
* 強さ・コスパの総合評価（PoC後）
* 類似馬・参考成績（定義は PoC。方針は血統類似度 / 生産牧場 / 調教師の組み合わせを検討）

### 3.3 調教師分析

* 単体検索・分析ダッシュボード
* 本年 / 前年 / 累計成績の表示（調教師マスタ CH）
* 競馬場別・距離別着回数の表示（CH にある項目）
* 最近重賞勝利情報の表示（CH）
* クラス別成績・新馬戦成績・勝ち上がり率（P1: MVP後。レース成績等からの追加集計）
* 年別成績の多年推移グラフ（P1: MVP後。CH は本年・前年・累計のみのため、JV-DL レース情報から追加集計する）

### 3.4 生産牧場分析

* 「生産牧場」は JV-DL の「生産者」と同一視する
* 最低限見たい指標: 出身馬の成績

### 3.5 血統分析

* 最低限見たい指標:
    * 距離適性（必須ではない）
        * JV-DL に SMILE 区分は無いため、レース実績・距離帯を SMILE へマッピングする
        * SMILE: S（スプリント） / M（マイル） / I（中距離） / L（長距離） / E（超長距離）
        * 例: 芝1600m以下 → S、1601〜2200m → M〜I、2201m以上 → L〜E（詳細は実装時に確定）
    * 馬場適性（芝 / ダート）
    * 兄弟の成績

### 3.6 募集馬の入力項目

募集馬の分析では以下を必須入力とする。

* 生年月日
* 性別
* 毛色
* 体重（募集時の体重。勝率との相関を見る可能性があるため保存する）
* 母名
* 父名
* 調教師
* 生産牧場
* 産地
* 市場取引価格（または 1口価格 × 口数）
* 馬主（一口クラブ名になる場合あり。例: サンデー / 社台 / シルク など）

#### 入力方法

* 馬名などをテキスト入力し、血統登録されている馬名の候補を表示して選択する（手入力 → 候補選択）

#### 市場取引価格の扱い

* 募集馬の分析では必須とする（1口価格 × 口数での入力も可）
* 分析に参照・使用する馬（類似馬等）で未取引・不明の場合はそのまま扱い、コスパ評価の対象外としてもよい（強さ分析のみ可）

## 4. スコープと優先度

### MVP（最初に作る範囲）

* **本実装（分析ロジック込み）**: 調教師の単体分析 + 可視化
    * 調教師検索・分析ダッシュボード
    * 本年 / 前年 / 累計成績
    * 競馬場別・距離別着回数
    * 最近重賞勝利情報
* **UI骨格のみ**（分析の本実装は後続）: 各機能の画面・導線を用意する
    * 募集馬1頭入力 → 分析ダッシュボード
    * 生産牧場の単体分析
    * 血統の単体分析
    * 類似馬・参考成績（表示枠。類似条件は未定）
* **MVPに含めない**
    * 強さ・コスパのスコアリング / 表示（PoC後）
    * 複数頭ランキング（強さ・コスパ）
    * 調教師の多年推移グラフ（P1。レース成績からの追加集計）
    * クラス別・新馬・勝ち上がり（P1）
* 今後の機能拡大に備え、拡張性・保守性を重視する
* 機能追加は branch でバージョン管理していく方針

### 優先度の考え方

* 分析の実装粒度の優先順: 調教師 → 生産牧場 → 血統（および総合評価の充実）
* 強さ・コスパの**方針**は各要素に共通して適用できる形で先に定め、**計算ルールは PoC で確定**する

### スコープ外

* 自動出資判断
* 予想印の自動生成
* 地方のみのデータ特化
* クラブ公式サイトのスクレイピング

### 将来機能（MVP外 / P1以降）

* 生産牧場分析・血統分析・類似馬の本実装
* 強さ / コスパ総合評価（PoC で計算式を確定してから）
* 複数頭ランキング
* 調教師の多年推移（レース成績からの追加集計）
* クラス別成績・新馬戦成績・勝ち上がり率の集計・表示
* 募集情報の PDF / CSV 等による一括取り込み（import）
* 一口出資額の併用
* その他外部データの追加取り込み

---

## 5. データソース

* 基本: JV-DL
* 当年の一口募集情報: 基本は手入力（JV-DL 外の可能性が高い）
* その他外部データ: 未定。今後追加したい（import 機能を想定）

### JV-DL 対応の目安

| 要求項目 | JV-DL での対応候補 | 備考 |
|---------|-------------------|------|
| 馬プロフィール | 競走馬マスタ (UM) | 生年月日・性別・毛色・血統・調教師・生産者・産地・馬主 |
| 調教師 | 調教師マスタ (CH) | 本年・前年・累計、競馬場別・距離別、最近重賞勝利。多年推移・クラス別等は要集計 |
| 生産牧場 | 生産者マスタ (BR) | 生産者＝牧場として扱う |
| 市場取引価格 | 競走馬市場取引価格 (HS) | 単位: 円。コスパ基準として意図的に使用 |
| 一口出資額・募集条件 | （JV-DL外） | 手動入力（1口価格・口数可）。将来は一括取り込み |
| 系統 | 系統情報 (BT) | 血統分析の補助 |
| レース成績 | 関連レースレコード | 多年推移・クラス別等の追加集計用 |

---

## 6. 非機能要求

### 利用形態

* デスクトップアプリを想定する
* Electron や Tauri などへの移植しやすい形態が望ましい

### データ更新

* 基本: アプリ起動後、更新ボタン等で手動更新する
* 設定による定期更新ができれば尚良いが、必須ではない
