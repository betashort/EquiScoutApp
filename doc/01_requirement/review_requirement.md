## 2. 「強さ」「コスパ」の定義（最重要）

現状: 「強い馬」「コスパが良い馬」とあるが、測り方が未定義。

### Q4. 「強さ」の一次指標は何か？（優先順に番号、または複数選択）

- [4] 収得賞金・本賞金
- [2] 勝率 / 連対率 / 複勝率
- [3] クラス到達（例: オープン以上）
- [5] 勝ち上がり（新馬・未勝利脱出）
- [1] 重賞実績
- [ ] その他

> 回答（一次指標と、あれば二次指標）:
> 1次指標: G1>G2>G3で重賞の勝てる確率が高い馬が強い
> 2次指標: 負けない馬が強い。必ず馬券内で安定感がある。大負けしない

### Q5. 「価格」は何を指すか？

- [ ] 一口出資額（クラブ募集価格）
- [x] 市場取引価格（JV-DL HS レコードあり）
- [ ] 両方を使う
- [ ] 未定

> 回答:
> JV-DLの市場取引価格を基準にする。

### Q6. 「コスパ」の計算イメージは？

例: `強さ指標 ÷ 価格`、`期待賞金 ÷ 出資額` など

> 回答:
> 強さ指標+価格


### Q7. アプリはスコアを出すべきか？

- [ ] 数値スコア・ランキングを出す
- [ ] 説明的な分析表示のみ（スコアなし）
- [x] 両方（スコア＋根拠の可視化）
- [ ] 未定

> 回答:
> スコアとその根拠となるデータをグラフ等で可視化する。

## 3. 機能・出力イメージ

現状: 「入力すると分析結果が表示される」のみで、何が返るか不明。

### Q8. 主な操作フローはどれか？

- [x] 1頭の募集馬を入力 → その馬の分析ダッシュボード
- [x] 複数頭を登録 → 比較表・ランキング
- [x] 調教師/牧場/血統を単体で調べる（馬入力なし）
- [ ] 上記の組み合わせ

> 回答:
> 複数の機能を持つ。
> 1. 1頭の募集馬を入力して、その馬の分析ダッシュボードを表示する。
> 2. 複数頭を入力して、ランキング(強さ指標・コスパ指標)を表示する。1頭の馬を選択すると1の分析ダッシュボードを表示する。
> 3. 調教師/牧場/血統を単体で、分析ダッシュボードを表示する。

### Q9. 入力後に必ず見せたい出力は？（複数可）

- [x] 調教師分析（年別・クラス別・新馬・勝ち上がり・推移）
- [x] 生産牧場（生産者）分析
- [x] 血統分析
- [x] 強さ・コスパの総合評価
- [x] 類似馬・参考成績
- [ ] その他

> 回答:
> 全て表示する。デフォルトの表示状態を設定できるようにしたい。

### Q10. 「生産牧場を分析したい」「血統を分析したい」で、最低限見たい指標は？

> 生産牧場:
> * 出身馬の成績

> 血統:
> * 距離適性(SMILE)
> * 馬場適性(芝/ダート)
> * 兄弟の成績

## 5. データソース

関連メモ:

| 要求項目 | JV-DL での対応候補 | 備考 |
|---------|-------------------|------|
| 馬プロフィール | 競走馬マスタ (UM) | 生年月日・性別・毛色・血統・調教師・生産者・産地・馬主 |
| 調教師 | 調教師マスタ (CH) | 本年・前年・累計成績あり。クラス別/新馬/勝ち上がりは要確認 |
| 生産牧場 | 生産者マスタ (BR) | 「牧場」＝「生産者」でよいか要確認 |
| 市場取引価格 | 競走馬市場取引価格 (HS) | 単位:円。あり |
| 一口出資額・募集条件 | （JV-DL外の可能性大） | 手動入力 or 別データ源が必要 |
| 系統 | 系統情報 (BT) | 血統分析の補助になりうる |

### Q15. 調教師の「クラス別成績」「新馬戦成績」「勝ち上がり率」について

調教師マスタ (CH) には本年/前年/累計の着回数・賞金はあるが、クラス別・新馬・勝ち上がりの直接項目は見当たらない。レース成績等からの集計が必要になる可能性が高い。

- [ ] MVPでは調教師マスタにある成績（賞金・着回数・競馬場別・距離別）で十分
- [ ] クラス別・新馬・勝ち上がりは必須（追加データ集計する）
- [x] 必須だが後回し（P1）
- [ ] 未定

> 回答:
> 必須だが後回し。今後、クラス別・新馬・勝ち上がりを追加できるように拡張性と保守性を重視したい。

### Q16. 市場取引価格がない馬（未取引・不明）の扱いは？

- [x] 価格入力を必須にしない（強さ分析のみ）
- [ ] 出資額を代替入力する
- [x] コスパ対象外として扱う
- [ ] 未定

> 回答:
> 募集馬の分析では必須にする。分析に参照/使用する馬の場合は未取引・不明はそのまま扱う。
